# Wimy MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Ship a public WebMCP room-planning vertical slice where a human and a browser agent fit, find, place, edit, export, import, and inspect furniture through one canonical room state.

**Architecture:** One strict portable Wimy room is held with a runtime revision in a Zustand store. Every human, WebMCP, template, import, and undo change crosses one atomic transaction interface; SVG 2D and React Three Fiber 3D are projections of the accepted room. A local curated catalog owns deterministic filtering and fit, while three imperative WebMCP tools reuse the same domain modules.

**Tech Stack:** Node 24.9.0, pnpm 9.15.9, Vite, React, TypeScript, Zustand, Zod, SVG, Three.js, React Three Fiber, Drei, Vitest, Testing Library, Playwright, imperative WebMCP.

**Spec:** docs/superpowers/specs/2026-08-29-wimy-mvp-design.md

## Global Constraints

- Official deadline is 2026-09-03 16:00 America/New_York; internal submission cutoff is 12:00.
- Feature freeze is 2026-09-02 12:00 America/New_York.
- One rectangular room; units are meters; origin is northwest; +x is east and +y is south.
- Item poses are footprint centers with clockwise 0, 90, 180, or 270 degree rotation.
- Runtime revision, receipts, undo, prompts, selection, and account data never enter a .wimy file.
- Only room/store.ts may hold the live Zustand writer, and transact(request) is its only room-changing interface.
- WebMCP exposes exactly inspect_room, find_furniture, and apply_room_edit.
- Catalog data is local and either fictional or owner-approved; no scraping, checkout, or freshness claim.
- No backend, auth, cloud sharing, editable 3D, external 3D models, or custom Wimy text parser.
- Tests drive each behavior through the same public interface used by callers.
- Where a step names several cases, execute them as separate red-green-refactor cycles: add one test, watch the expected behavioral failure, implement the minimum, and rerun the focused suite before adding the next case.
- Each Linear issue uses its own branch/worktree, records sanitized evidence under ignored .docs/evidence/, and ends in review.
- Commit messages include the actual REL identifier. Agents do not push.

export type RoomWarning =
  | { code: "OVERLAP"; message: string; itemIds: [EntityId, EntityId] }
  | { code: "DOOR_CLEARANCE"; message: string; itemIds: [EntityId] }
  | { code: "CATALOG_UNAVAILABLE"; message: string; itemIds: [EntityId] };

export type ActivityReceipt = {
  origin: TransactionOrigin;
  status: "accepted" | "rejected";
  revision: number;
  summary: string;
  code?: TransactionFailureCode;
  affectedItemIds: EntityId[];
};

export type RoomTransactionResult =
  | {
      ok: true;
      revision: number;
      applied: number;
      affectedItemIds: EntityId[];
      warnings: RoomWarning[];
      receipt: ActivityReceipt;
    }
  | {
      ok: false;
      revision: number;
      code: TransactionFailureCode;
      message: string;
      warnings: RoomWarning[];
      receipt: ActivityReceipt;
    };

export type RoomTransactionOutcome = {
  state: RuntimeRoomState;
  result: RoomTransactionResult;
};

export type ResolvedProduct = {
  catalogRef: { catalogId: string; productId: string };
  snapshot: FurnitureSnapshot;
};

export type ProductResolver = (
  productId: string,
) => ResolvedProduct | undefined;

export type TransactionDependencies = {
  resolveProduct: ProductResolver;
  createItemId: () => EntityId;
};

export const TEST_TRANSACTION_DEPENDENCIES: TransactionDependencies = {
  resolveProduct: () => undefined,
  createItemId: () => "item_generated_1",
};
~~~

Runtime revision starts at 1. A success result contains ok, revision, applied, affectedItemIds, warnings, and receipt. A failure contains ok, unchanged revision, code, message, warnings, and receipt. RoomTransactionOutcome always returns the next or unchanged state beside that public result.
